# Участие в разработке Gamaj Node

Спасибо за помощь. В проекте действует небольшой набор обязательных правил; прочитайте их до написания кода — pull request, нарушающий их, не будет принят.

## Красные линии

1. **Только имя Gamaj.** Никаких упоминаний других панелей, нод или скриптовых проектов в коде, комментариях, текстах интерфейса, документации или ресурсах. Автоматический guard по именам окружений и проверка следов роняют сборку, если такое имя появляется.
2. **Никаких следов агентов.** Не упоминайте ИИ-ассистентов, агентов или инструменты автоматизации в коде, сообщениях коммитов или документации. Коммиты должны выглядеть как обычная работа разработчика.
3. **Один путь установки: нативный бинарник + systemd.** Никакого Docker, compose-файлов и переключателя режимов установки; ни одна функция не отключается в зависимости от режима установки. Все VPN-бэкенды (OpenVPN, WireGuard, AmneziaWG, L2TP, PPTP, SSTP и MTProto-прокси) поставляются включёнными.
4. **Каждая переменная окружения начинается с `GAMAJ_NODE_`** (или `GAMAJ_` для значений, общих с панелью). Исключения — имена, принадлежащие ОС или сторонним инструментам, например `PATH`; они перечислены в guard.
5. **Порт 62050** остаётся портом управления ноды по умолчанию (Xray API следует на 62051).
6. **Документация самодостаточна.** Документация не должна отправлять читателя на GitHub или другой сайт «за подробностями»; контент находится в этом репозитории (и на сайте `Web/`).

## Процесс работы

1. Форкните или создайте ветку от `Asli`.
2. Держите изменения сфокусированными; одна тема на pull request.
3. Запускайте проверки, относящиеся к вашим правкам:

```bash
cd Node
gofmt -l .                       # без вывода
go build ./... && go vet ./internal/... ./cmd/...
go test ./internal/config/ ./internal/platform/envguard/

# если меняли установщик или тесты:
bash -n scripts/gamaj/gamaj-node.sh scripts/tests/e2e-node-install.sh

# полная end-to-end установка (Linux + systemd + root, CI запускает её на каждый push):
sudo bash scripts/tests/e2e-node-install.sh
```

4. Если затронуто что-то в `internal/xray/`, прогоните весь набор тестов:
   `go test ./...`.

## Сообщения коммитов

Короткие, в повелительном наклонении, о сути изменения, например:

```
Fail fast when the Xray binary cannot be executed
Report WireGuard handshake age in the node status
```

Не добавляйте подписи инструментов, строки вида generated-by или co-author-трейлеры. Автор и коммитер должны быть вашим собственным Git-идентификатором.

## Стиль кода

- Go: `gofmt`, `go vet`, оборачивание ошибок через `%w`, табличные тесты рядом с пакетом, который они покрывают.
- Shell: `set -euo pipefail`, опции с префиксом `GAMAJ_NODE_`, никаких внешних зависимостей помимо обычных POSIX-утилит плюс `curl`, `jq` и `tar`.
- CI-артефакты: AmneziaWG и пакет accel-ppp собираются на нативных раннерах с тулчейном musl — никогда не возвращайте контейнерный runtime.

## Вендоренный код

Дерево `vendor/` — обычный каталог Go vendor; держите его согласованным с `go.mod`. Не правьте вендоренные пакеты вручную и не допускайте утечки правил `.gitignore` в `vendor/` (правила игнорирования для рантайм-загрузок должны быть заякорены, например `/xray-core`).

## Сообщение о проблемах

Указывайте: версию ноды (`gamaj-node version` или тег релиза), ОС и архитектуру, вывод журнала (`journalctl -u gamaj-node -n 100`) и минимальные шаги воспроизведения. Вопросы безопасности передавайте мейнтейнерам приватно — не создавайте публичный issue для того, что может быть эксплуатируемым.
